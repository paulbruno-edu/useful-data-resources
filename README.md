# Useful Data Resources

A searchable list of free data sources for quantitative research in education, published at
<https://data.paul-bruno.com>.

## How it's maintained

The list itself lives in a workbook outside this repository, in Google Drive:

```
C:\GoogleDrive\UIUC\Projects\usefuldataresources\useful_data_resources.xlsx
```

It stays out of the repository because it holds private review notes and Git handles Excel files poorly.
The scripts that publish it live here, in `scripts/`. The workbook's location is set once, in
`scripts/export_site.py` (`WORKBOOK`), or for a one-off run with the `USEFUL_DATA_WORKBOOK` environment
variable.

To update the site:

1. Edit the workbook, save, and close it in Excel.
2. In this folder, run `python scripts/publish.py`. It stops and lists any problems (a missing link, a value
   that isn't in the lists tab, a duplicate name, a Start here source without details). Otherwise it
   publishes, and GitHub Pages updates in about a minute. `python scripts/publish.py --dry-run` checks and
   exports without publishing.

`publish.py` publishes what the export generates: the `data/` folder, the plain-HTML copy of the lists inside
`index.html` (for search engines), and `sitemap.xml`. Other changes (`assets/`, `guide.html`, `scripts/`,
or hand edits to `index.html`) are committed and pushed separately, with GitHub Desktop.

Each run also lists the five sources reviewed least recently, using the workbook's Last reviewed column.
A working link doesn't mean a source's contents or access rules are unchanged, so checking a few by hand
each time keeps the descriptions accurate.

## What's here

| Path | What it is |
|---|---|
| `index.html`, `guide.html`, `assets/` | The pages. When you change `app.js`, `style.css`, or `count.js`, bump the `?v=` numbers in the HTML so browsers fetch the new copy. |
| `data/` | Generated by `scripts/export_site.py`. Don't edit by hand. |
| `scripts/publish.py` | Checks the workbook, exports, commits, and pushes. |
| `scripts/export_site.py` | The export step on its own; also where the workbook's location is set. |
| `scripts/check_workbook_links.py` | Rechecks every link in the workbook and updates its Link status and Last checked columns. Close the workbook first. |
| `scripts/check_links.py` | Used by the monthly GitHub Action below; checks the published data, not the workbook. |
| `assets/count.js` | Visit and search counting with GoatCounter (code `paulbrunodata`). |
| `CNAME`, `robots.txt`, `sitemap.xml` | Custom domain and search engine files. The sitemap is regenerated on export. |

The scripts need Python with `openpyxl` installed.

## Linking to one source

Each entry has a link of the form `https://data.paul-bruno.com/?source=<id>`, where the ID is the
source's name in lowercase with dashes (e.g., `common-core-of-data`). Renaming a source in the workbook
changes its ID, so older links to it will show a "may have been renamed" message.

## Monthly link check

`.github/workflows/check-links.yml` checks every link in `data/resources.json` on the 3rd of each month.
If any link is broken (404 or 410), the run fails and GitHub emails you; the run's log lists the
broken links. Sites that block automated checks are reported but don't fail the run.
