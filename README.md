# Useful Data Resources

A searchable list of free data sources for quantitative research in education, published at
<https://data.paul-bruno.com>.

## How it's maintained

The list itself lives in a workbook outside this repository:

```
C:\GoogleDrive\UIUC\Projects\usefuldataresources\
├── useful_data_resources.xlsx   the master list (edit this)
├── publish.py                   checks the workbook, exports it here, commits, and pushes
├── export_site.py               the export step on its own; also says where this repository lives (SITE_REPO)
└── check_links.py               rechecks every link and updates the workbook's Link status column
```

To update the site:

1. Edit the workbook, save, and close it in Excel.
2. Run `python publish.py` in that folder. It stops and lists any problems (a missing link, a value that
   isn't in the lists tab, a duplicate name). Otherwise it publishes, and GitHub Pages updates in about a
   minute. `python publish.py --dry-run` checks and exports without publishing.

`publish.py` publishes what the export generates: the `data/` folder, the plain-HTML copy of the lists inside
`index.html` (for search engines), and `sitemap.xml`. Other changes to the page (`assets/`, `guide.html`, or
hand edits to `index.html`) are committed and pushed separately, with GitHub Desktop.

Each run also lists the five sources reviewed least recently, using the workbook's Last reviewed column.
A working link doesn't mean a source's contents or access rules are unchanged, so checking a few by hand
each time keeps the descriptions accurate.

## What's here

| Path | What it is |
|---|---|
| `index.html`, `assets/` | The page. When you change `app.js` or `style.css`, bump the `?v=` numbers in `index.html` so browsers fetch the new copy. |
| `data/` | Generated by `export_site.py`. Don't edit by hand. |
| `scripts/check_links.py` | Used by the monthly GitHub Action below. |
| `CNAME` | The custom domain for GitHub Pages. |

## Monthly link check

`.github/workflows/check-links.yml` checks every link in `data/resources.json` on the 3rd of each month.
If any link is broken (404 or 410), the run fails and GitHub emails you; the run's log lists the
broken links. Sites that block automated checks are reported but don't fail the run.
